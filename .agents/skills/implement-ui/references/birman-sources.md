# Sources and interpretation boundaries

These Russian-language primary sources were consulted on September 24, 2026. The English titles and notes below are translations and paraphrases, not quotations. Use the article body as evidence; reader comments are not Birman's advice. The collection is selective and does not reproduce his paid book or course.

## 1. User scenarios

[How to write user scenarios](https://bureau.ru/soviet/20260825/)

Scenarios describe the person's circumstances, information, constraints, and intended result before an interface is designed. Screen sequences and system reactions belong to a different level of specification.

## 2. Direct access to useful destinations

[The unnecessary account area](https://ilyabirman.ru/meanwhile/all/lishniy-kabinet/)

Expose destinations such as orders or shipment tracking directly and identify the visitor when needed. Apply the argument to unnecessary intermediate steps; it does not establish that protected information should be public.

## 3. Form syntax

[What is the syntax of interface elements?](https://bureau.ru/bb/soviet/20170207/)

The heading, fields, and command form a coherent construction. Reduce repetition while retaining specificity. Long forms may need fuller labels because the heading and final action are not visible together.

## 4. Buttons

[Tell us about the button](https://bureau.ru/soviet/20230509/)

Button functions include commands, status assignment, and navigation; their wording differs accordingly. Recognition, pointing, feedback, visual priority, and interaction states all matter.

## 5. Checkboxes

[Tell us about the checkbox](https://bureau.ru/soviet/20250225/)

Use direct labels and an obvious unchecked meaning. If the alternative is unclear, name the options explicitly. Clickable labels improve targeting; embedded links can interfere with this behavior.

## 6. Disabled actions

[A disabled button in a registration form](https://bureau.ru/soviet/20240521/)

Disabled commands preserve interface stability and can communicate that a form is incomplete. The risk of misunderstanding increases in unfamiliar forms. Birman's position is contextual, not a blanket prohibition.

## 7. Purchase actions

[The Buy button is always available](https://ilyabirman.ru/meanwhile/all/buy-works/)

In the rental example, clicking without dates opens date selection. Accepting a booking when the vehicle is unavailable relies on staff arranging alternatives or a refund. Do not generalize that business arrangement to systems without such a capability.

## 8. Labels and layout evidence

[Google study: users read more easily with labels above fields](https://bureau.ru/soviet/20180109/)

Birman criticizes attributing an improvement to label position when spacing, field sizes, and action placement also changed. This supports evaluating the whole composition, not dismissing usability research.

## 9. Pointing and Fitts's law

[Making interface targets easier to hit, part one](https://bureau.ru/bb/soviet/20160517/)

Larger, nearer targets are easier to acquire, with diminishing gains from enlargement. Separate controls whose accidental substitution would be undesirable. This is Birman's application of Fitts's law, not a law of his own.

## 10. Vertical stacks

[The list as a way of organizing an interface](https://ilyabirman.ru/meanwhile/all/vertical-stack-ui/)

Vertical layouts adapt easily but can waste wide screens and force unnecessary scrolling. The article also recognizes suitable uses, including narrow screens and sidebars.

## 11. Modes and modal dialogs

[Why is modality used?](https://bureau.ru/soviet/20251021/)

Hiding controls through modes can increase complexity. Blocking dialogs reduce the designer's branching burden but may interrupt the user's work. Birman distinguishes these topics and acknowledges that modes cannot always be eliminated.

## 12. Completeness checks

[Interface completeness: checking questions](https://ilyabirman.ru/meanwhile/all/completeness-questions/)

Check action outcomes, reopening hidden content, extreme values, varying list lengths, and live changes. The article labels this set of questions a draft. Loading, retry, and accessibility checks in the skill are practical additions, not quotations from this list.

## 13. Component libraries

[Asked to make a design system](https://bureau.ru/soviet/20220118/)

Begin with proven components, implement shared reuse, test real variations, and extend the library as product needs arise. A comprehensive library is not an end in itself.
