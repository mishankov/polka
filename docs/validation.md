# Проверка и ограничения

`npm run verify` проверяет типы, сборку, Swift-пробы, unit-тесты, полку, историю буфера и индикатор камеры/микрофона. Desktop-проверки используют отдельные временные профили.

Тест worker проверяет сохранение существующих настроек, неизменность старых таблиц и отказ удалённых RPC, включая провайдеры, приложения, задания, расширения и пакеты. Проверка полки включает настройки, сочетания, навигацию, скрытый Dock и запуск без окна при `--hidden`.

`npm run test:clipboard:paste` отдельно проверяет вставку в другую программу и требует разрешения «Универсальный доступ». Для готового приложения доступны `test:packaged` и `test:packaged:workflows`.

Приложение поддерживает macOS 27+ на Apple silicon. Индикатор сообщает доступные сведения системных устройств и может показывать неизвестное состояние. Он не записывает видео или звук. Во время сна и блокировки наблюдение приостанавливается.

GitHub Actions запускает проверку, упаковку и smoke-тест готового `.app` на Apple silicon/macOS 27 (`xcode-27`) для pull request и push в `master`. В `build.yml` параллельно работают две группы проверок исходников (`desktop`: типы, unit-тесты, полка и эмодзи; `workflows`: буфер и медиа-индикатор), упаковка с проверкой готового приложения и три режима теста обновления: ad-hoc, self-signed и переход с ad-hoc на self-signed. Каждая группа использует отдельный runner: буфер обмена, фокус и системные сочетания нельзя делить между одновременно работающими GUI-тестами. Ubuntu-job сначала проверяет изменённые пути и переводы примечаний. Если изменены только README, Markdown-документация, примечания к выпускам или инструкции агентов, macOS jobs пропускаются; любые другие пути и ручной запуск требуют полного набора. Итоговая проверка `Verify and package macOS arm64` требует успеха всех macOS-заданий либо успешной лёгкой проверки с намеренными пропусками и сохраняет имя для branch protection. Ошибка определения изменений или отменённая проверка не считаются успехом. Артефакты сборки и снимки desktop-проверок доступны из workflow.

Unit-тесты обновлений проверяют оба языка примечаний, сохранение пропущенной версии, напоминание через 24 часа и отказ сохранения выбора. Desktop-тест настоящего обновления проверяет карточку, переключение языка, пропуск, напоминание и установку. Тесты подписи и миграции не доказывают сохранение Accessibility- и Keychain-разрешений на пользовательском Mac; отдельная приёмка описана в [macos.md](macos.md#проверка-настоящего-обновления).

В `release.yml` подготовка и загрузка выполняются на Linux. Подготовка один раз разрешает исходники в commit SHA и проверяет обе локализации `release-notes/VERSION.json` из этого commit до создания нового черновика/тега. Обе группы проверок исходников и упаковка выпуска работают параллельно на macOS с этим SHA. Загрузка начинается только после успеха всех проверок. Подписанный appcast загружается после архивов, а опубликованные архивы не перезаписываются. Описание GitHub Release берётся из тех же проверенных переводов и синхронизируется до публикации черновика. Unit-тест подготовки запускает реальный shell workflow с локальным Git и изолированной подменой GitHub: проверяет отказ до создания тегов при ошибке примечаний, выбор точного commit, повтор черновика, старые выпуски и смену тега во время подготовки.

`npm run build:prepare` собирает JavaScript и Swift-пробы. После него `npm run package:prepared`, `npm run release -- --prebuilt` и `npm run test:updates -- --prebuilt` используют готовые результаты без повторной компиляции. Эти команды нужно запускать в том же checkout сразу после подготовки; `--prebuilt` проверяет наличие выходных файлов, но не их актуальность. Обычные `package`, `release` и `test:updates` сами подготавливают приложение. В CI каждый runner собирает исходники один раз; Sparkle bridge собирается отдельно только для выпуска и теста обновления.

React, React DOM и Tabler находятся в `devDependencies`: Vite включает используемый код в renderer, а исходные npm-пакеты в `.app` не нужны. Zod, selfsigned и Sparkle остаются runtime-зависимостями. ZIP временного теста обновления создаётся без сжатия для ускорения, но подписи, отказ неверной подписи, установка и перезапуск проверяются как прежде. Выпуск сохраняет обычное сжатие; готовые DMG/ZIP загружаются в Actions без повторного сжатия.
