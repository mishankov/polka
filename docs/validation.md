# Проверка и ограничения

`npm run verify` проверяет типы, сборку, Swift-пробы, unit- и integration-тесты, полку, историю буфера и индикатор камеры/микрофона. Desktop-проверки используют отдельные временные профили.

В suite `shelf` входит `clipboard-startup-smoke.ts`: управляемый помощник задерживает готовность до команды теста. Проверка запускает настоящее приложение, подтверждает автоматическое открытие полки до готовности, копирование сохранённой записи при ожидании, статус в истории и настройках, сохранение поиска после повтора и исчезновение статуса при восстановлении. Буфер и шифрование подменены только в fixture, без обращения к пользовательским Keychain- и Accessibility-разрешениям. Renderer-fixture отдельно проверяет статус в эмодзи и при выключенной автовставке.

Общий harness `tests/desktop/desktop-test.ts` сериализует GUI-проверки на одном Mac, нормализует окружение Electron, сохраняет буфер в памяти между перезапусками fixture, ограничивает закрытие по времени и ждёт выхода процессов перед удалением профиля. Проверки открытия/закрытия полки учитывают нативную видимость и фокус. При ошибках CI сохраняет снимки, traces и состояние fixture из `artifacts/desktop/`. [Запуск и диагностика](development.md).

`tests/integration/shelf-services.test.ts` проверяет независимый запуск помощника при ошибках чтения, расшифровки и формата истории, сохранение исходной причины и файлов, отказ записи, отдельные состояния разрешения и помощника и изоляцию ошибки синхронизации. После сборки `npm run test:desktop -- clipboard-storage` проверяет сообщения в истории и настройках, отключённые связанные настройки, копирование эмодзи, восстановление после перезапуска и копирование ранее сохранённых записей при ошибке записи. Этот smoke использует одноразовый профиль, инъекции ошибок и буфер в памяти; он не проверяет реальную причину прежнего сбоя расшифровки или доступ к пользовательскому Keychain.

Тест worker проверяет сохранение существующих настроек, неизменность старых таблиц и отказ удалённых RPC, включая провайдеры, приложения, задания, расширения и пакеты. Проверка полки включает настройки, сочетания, навигацию, скрытый Dock и запуск без окна при `--hidden`.

`shelf-smoke.ts` проверяет восстановление открытого встроенного приложения при быстром повторном открытии, возврат к программам после минуты закрытия и приоритет явной навигации. Время в этих сценариях управляется тестом; проверка ждёт завершения открытия перед следующим переходом и отдельно сверяет нативные видимость/фокус. `shelf-lifecycle.test.ts` проверяет границу 60 000 мс, повторное скрытие, отменённую подготовку и устаревшие подтверждения. Renderer-fixture проверяет полный контекст истории/эмодзи, свежий явный вход, сброс меню/подтверждений, защиту от IME и повторов, ⌘1–9 у эмодзи, единственную стрелку назад и двухстрочное уведомление в общей прокрутке.

Тесты каталога проверяют локализованные названия из `InfoPlist.strings` и `InfoPlist.loctable`, смену языка при сохранении ID/иконок и поиск по исходному английскому имени.

Загруженный каталог и статистика запуска живут в renderer дольше отдельного открытия полки: возврат из встроенного приложения и повторное открытие сразу показывают прежний список, затем обновляют его в фоне. `shelf-search-shortcuts-smoke.ts` задерживает ответ каталога, проверяет наличие macOS-приложений уже при `shelf.didShow`, доступность поиска, появление нового приложения после обновления и сохранение прежних результатов при ошибке с последующим повтором. Первое получение каталога после холодного запуска остаётся асинхронным; дискового кэша списка нет.

Тесты поиска проверяют опечатки, начальные буквы, обе раскладки, приоритет точных совпадений, устойчивость порядка и большой каталог. Тесты `LauncherUsage` проверяют сохранение статистики после перезапуска, отказ запуска, одновременные записи и ошибки хранения. Desktop-проверка `shelf-search-shortcuts-smoke.ts` проверяет запуск найденного приложения стрелками, Enter и ⌘1–9, обновление подсказок после изменения порядка и сохранение выбранной записи при её перемещении.

`conversions.test.ts` проверяет перевод четырёх величин, обе локализации, температурные смещения и абсолютный ноль, неоднозначные единицы, зимние/летние смещения, переход дат, неполные запросы и сохранение правил поиска. Для времени проверяются повторения и пропуски при часовом и получасовом переводе, пропуск даты при переходе линии перемены дат, високосные даты и закрепление даты при копировании после полуночи. Desktop-проверки поиска и буфера проверяют клавиатуру и клик, содержимое системного буфера, сохранение фокуса и отсутствие новых записей истории при копировании результата.

`npm run test:desktop -- clipboard-paste` отдельно проверяет вставку в другую программу и требует разрешения «Универсальный доступ». Для готового приложения доступны `npm run test:desktop -- shelf --packaged` и `npm run test:desktop -- workflows --packaged`.

`npm run test:desktop -- clipboard-paste --dev` запускает настоящий Vite-renderer разработки и проверяет повторные открытия в одном процессе. Проверка включает новые цели после вставки, Escape и ⇧ Enter; задержанную запись буфера при уходе указателя и событии native `blur`; явное закрытие с повторным открытием до завершения старой записи. Автоматическое закрытие ждёт выбранного действия, а явное закрытие и новое открытие отменяют его право на вставку. Содержимое целевого поля и native-видимость проверяются отдельно от DOM-фокуса; указатель, задержка записи и запоздалое событие `blur` моделируются в main-процессе. Буфер, native-вставка, восстановление поля и его выделения остаются настоящими. Тест использует отдельное Electron-приложение с обычным и пересоздаваемым редактором; поля T3 Code и Terminal требуют ручной проверки.

`clipboard-actions.test.ts` проверяет смену регистра и проверку веб-ссылок. `npm run test:desktop -- clipboard-actions` проверяет просмотр результата, возвращение оригинала, копирование преобразованного текста (включая ⇧ Enter), сохранность истории, явное открытие ссылки, запись полного PNG и отмену из списка, видимую ошибку записи и повтор из просмотра. В этом desktop-тесте открытие браузера и ответ системного диалога подменяются; IPC, история, буфер обмена и запись файла остаются настоящими. Потеря фокуса при диалоге моделируется событием `blur`. Для проверки настоящего диалога запустите `npm run test:desktop -- clipboard-actions --native` и нажмите «Отмена» в появившемся диалоге. `npm run test:desktop -- clipboard-paste` включает вставку преобразованного текста в другую программу; без Accessibility-разрешения проверяется только копирование.

Проверка действий также использует ⌘1–3 для преобразований, оригинала и сохранения изображения, сверяет подсказки сочетаний и отказ недоступного действия. Ссылки открываются, а изображения сохраняются кнопками прямо в списке и сочетанием ⌘⌥1–9; проверяется отсутствие кнопки открытия ссылки в просмотре, у неподдерживаемых ссылок и изображений. Backspace проверяется при возврате из просмотра с сохранением запроса, редактировании непустого поиска, отмене подтверждения очистки и возврате к приложениям из пустого поиска. Повтор удерживаемой клавиши не запускает действие повторно.

Приложение поддерживает macOS 27+ на Apple silicon. Индикатор сообщает доступные сведения системных устройств и может показывать неизвестное состояние. Он не записывает видео или звук. Во время сна и блокировки наблюдение приостанавливается.

GitHub Actions запускает проверку, упаковку и smoke-тест готового `.app` на Apple silicon/macOS 27 (`xcode-27`) для pull request и push в `master`. В `build.yml` обе группы исходников выполняются последовательно на одном runner через `npm run verify -- --prebuilt`: форматирование, типы, Node-тесты, полка, эмодзи, OCR, файловая полка, буфер и медиа-индикатор. Параллельно на отдельных runners работают упаковка с проверкой готового приложения и три режима теста обновления: ad-hoc, self-signed и переход с ad-hoc на self-signed. Всего используется пять macOS runners; буфер обмена, фокус и системные сочетания нельзя делить между одновременно работающими GUI-тестами. В hosted CI реальное распознавание Vision заменено синтетическим только в OCR-проверках из-за ошибки компиляции модели Apple; проверка очереди, хранения, поиска и интерфейса остаётся настоящей. Проверка нативного Vision выполняется локально, как описано в [development.md](development.md). Фильтры `paths-ignore` в `on.push` и `on.pull_request` не запускают workflow для изменений только README, Markdown-документации, примечаний к выпускам или инструкций агентов. Остальные пути и ручной запуск требуют полного набора. `docs/unicode-license.txt` входит в приложение и не исключён из проверки. Итоговая проверка `Verify and package macOS arm64` требует успеха всех macOS-заданий и сохраняет имя для branch protection. Переводы примечаний проверяются локальной командой и подготовкой `release.yml` до создания выпуска. Артефакты сборки и снимки desktop-проверок доступны из workflow.

Unit-тесты обновлений проверяют оба языка примечаний, сохранение пропущенной версии, напоминание через 24 часа и отказ сохранения выбора. Desktop-тест настоящего обновления проверяет карточку, переключение языка, пропуск, напоминание, установку и готовность clipboard helper в процессе, который перезапустил Sparkle. `shelf-services.test.ts` проверяет восстановление после тайм-аута, увеличенный срок следующей попытки, ожидание выхода старого процесса, защиту от его поздних событий, предел повторов и отмену при завершении приложения. Тесты подписи и миграции не доказывают сохранение Accessibility- и Keychain-разрешений на пользовательском Mac; отдельная приёмка описана в [macos.md](macos.md#проверка-настоящего-обновления).

В `release.yml` подготовка и загрузка выполняются на Linux. Подготовка один раз разрешает исходники в commit SHA и проверяет обе локализации `release-notes/VERSION.json` из этого commit до создания нового черновика/тега. Обе группы проверок исходников и упаковка выпуска работают параллельно на macOS с этим SHA. Загрузка начинается только после успеха всех проверок. Подписанный appcast загружается после архивов, а опубликованные архивы не перезаписываются. Описание GitHub Release берётся из тех же проверенных переводов и синхронизируется до публикации черновика. Unit-тест подготовки запускает реальный shell workflow с локальным Git и изолированной подменой GitHub: проверяет отказ до создания тегов при ошибке примечаний, выбор точного commit, повтор черновика, старые выпуски и смену тега во время подготовки.

`npm run build` собирает JavaScript и Swift-пробы. После него `npm run package -- --prebuilt`, `npm run release -- --prebuilt` и `npm run test:desktop -- updates --prebuilt` используют готовые результаты без повторной компиляции. Эти команды нужно запускать в том же checkout сразу после подготовки; `--prebuilt` проверяет наличие выходных файлов, но не их актуальность. Обычные `package`, `release` и `npm run test:desktop -- updates` сами подготавливают приложение. В CI каждый runner собирает исходники один раз; Sparkle bridge собирается отдельно только для выпуска и теста обновления.

React, React DOM и Tabler находятся в `devDependencies`: Vite включает используемый код в renderer, а исходные npm-пакеты в `.app` не нужны. Zod, selfsigned и Sparkle остаются runtime-зависимостями. ZIP временного теста обновления создаётся без сжатия для ускорения, но подписи, отказ неверной подписи, установка и перезапуск проверяются как прежде. Выпуск сохраняет обычное сжатие; готовые DMG/ZIP загружаются в Actions без повторного сжатия.

Проверка сниппетов также проверяет подсказки ⌘N и ⌘Enter на кнопках и `aria-keyshortcuts`, сохранение из обоих полей редактора, запрет сохранения пустого текста, защиту от повторного сохранения и сохранение черновика при конфликте, открытие редактора кнопкой и сочетанием из поиска и просмотра, русскую раскладку, защиту черновика при повторном ⌘N, а также игнорирование удержания клавиши, IME-композиции и лишнего модификатора. При синтетической широкой выемке проверяются однострочная надпись, компактная высота и размещение кнопки вне выемки; сохраняется снимок состояния наведения.

`npm run test:desktop -- clipboard-snippets` проверяет настоящее приложение и IPC: отдельный пункт «Сниппеты» в каталоге, пустой список, прямое создание без исходной записи, переход из истории в редактор, изменение текста, пустой текст, восстановление незавершённого редактора при быстром повторном открытии, поиск в сниппетах и на полке после перезапуска, отсутствие сниппетов в истории, сохранение исходной записи, очистку истории без удаления сниппетов и отдельный переход к полному списку сниппетов с полки, копирование текста без названия, передачу команды вставки синтетическому помощнику и сохранение черновика при конфликте изменений. Проверка использует общий desktop harness, скрытые окна, подменённые буфер, шифрование, нативный помощник и сочетания, поэтому не меняет пользовательский буфер и не забирает фокус. Снимки синтетических данных сохраняются в `artifacts/desktop/clipboard-snippets/`. Реальные Keychain- и Accessibility-разрешения этим сценарием не проверяются. Unit- и TLS-тесты проверяют создание при записи буфера на паузе, миграцию прежней смешанной коллекции, независимые лимиты и срок хранения, стабильный ID, дубликаты, сохранение прежнего статуса закрепления, сходимость одновременных изменений и удалений, очистку истории при отключённом Mac и совместимость с клиентом без поддержки сниппетов.

`npm run test:desktop -- shelf-startup` задерживает подтверждение первого показа renderer на 2,5 секунды и проверяет, что приложение остаётся запущенным, дожидается готовности и выполняет вычисление клавиатурой. Проверка использует настоящее ядро и renderer, временный профиль и общий desktop harness; системный буфер, шифрование, глобальные сочетания, нативные помощники и показ/фокус окна подменены. Первый renderer получает до 10 секунд на подготовку; последующие открытия — до двух секунд. Integration-тесты проверяют оба предела и отказ запоздалого подтверждения после тайм-аута. Диагностика desktop harness сохраняет последние 65 536 символов stdout/stderr каждого тестового процесса, включая ошибки запуска до появления интерфейса.
