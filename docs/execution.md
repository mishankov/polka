# Local execution and automation

`ExecutionService` persists jobs and automation state through `CoreService.state.get/set`, backed by SQLite in the trusted worker. Closing a React page does not stop the worker. Jobs allow two concurrent operations and at most 100 queued/running jobs. `jobs.enqueue({appId, actionId, input?, timeoutMs?, idempotencyKey?, maxAttempts?})` validates the app and declared action. Status, progress, results and errors are visible through `jobs.list` and events. `jobs.cancel` aborts the shared signal. Default timeout is 60 seconds; accepted bounds are 1–300 seconds. Inputs are limited to 16 MiB. Executors must observe AbortSignal; timeout cannot undo an already completed external effect.

Retries are derived from registered action type. Pure transforms and record queries can retry up to three attempts when requested. Other operations never automatically retry, regardless of caller-supplied retry flags. A scoped idempotency key returns the previous job for the same instance/action/key. This is local duplicate suppression, not universal exactly-once execution. Any persisted `running` job becomes `interrupted` on restart with an explicit ambiguous-effect warning; it is never blindly replayed. Persisted queued work resumes. App stopping, archiving or permission revocation asks the runtime to abort jobs and disable watchers.

Automations are separate persistent records with trigger, action, configuration, enabled state, last result and a bounded 100-event history. Supported triggers:

- `interval`: minimum one second, maximum one day.
- `schedule`: daily wall time `{timezone, hour, minute}` using a validated IANA timezone, default `Europe/Moscow`.
- `clipboard`: checks once per second, hashes text to detect changes, sends only changed text to the declared action. The initial sample and first post-resume sample do not create events.
- `event`: matches an explicitly injected host event name.

Enabled automations require the platform `background` grant; clipboard additionally requires `clipboard.read`. Checks repeat before observations and dispatch. Revocation disables the watcher before another clipboard read. Each action independently checks its capability permissions in the trusted executor. App definitions declare rules, but `runtime.syncApp` installs new rules paused. Stable declaration IDs prevent duplicate registrations. Local edits are preserved; changed declarations disable the local rule and request review. Removed declarations disable it. Imports never acquire grants or enable watchers.

Schedule missed-run policy is explicit in `config.missed`: `skip`, `once` (default), or `catchup`. Catch-up is capped at ten and defaults to three via `catchupLimit`. A five-second grace handles ordinary polling jitter; later times count as missed. An interval advances to the next future boundary rather than drifting. Daily schedules use wall-clock timezone conversion, skip nonexistent spring-forward times, and suppress the second occurrence of a fall-back wall time. Sleep pauses dispatch; resume re-evaluates missed deadlines and clears the clipboard baseline. A computer that is asleep/off cannot execute local jobs. Clock changes are handled on the next tick by comparing the persisted absolute deadline; timezone changes take effect when editing the rule.

`runtime.signal({event:'suspend'|'resume',data?})` is injected by the shell's power monitor. `runtime.stopApp({appId})` and `runtime.syncApp({appId})` are trusted lifecycle hooks. No renderer is required. Long-running integrations other than clipboard are represented through injected events; arbitrary reconnecting third-party subscription drivers are not included.

Tests cover actual queue persistence behavior, idempotency, cancellation, unsafe retry prevention, crash ambiguity, permission revocation, timezone/DST scheduling, and rule synchronization using an in-memory CoreService contract. Native sleep/resume and external clipboard changes still require the reproducible macOS protocol in the main verification documentation. No measured performance claim follows from mock tests.

Rules can additionally set `config.conditions` to up to 20 predicates `{path, operator, value}`. All predicates must match the trigger input; operators are `eq`, `neq`, `contains`, `gt`, and `lt`. Event payloads are under `data`, clipboard content under `text`, and schedule input has `scheduledAt`. Traversal uses own JSON properties and excludes prototype keys. A nonmatching trigger creates no job. Queued jobs capture the definition version and fail safely if an update changes that version before execution; they never silently switch to a new action implementation.
