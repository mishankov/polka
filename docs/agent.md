# Agent and provider runtime

The runtime is `src/runtime/service.ts`; provider adapters are in `providers.ts`. Both OpenAI-compatible Chat Completions and Anthropic Messages use native Node fetch and incremental SSE parsing. No provider SDK is required. Endpoint configuration permits HTTPS or HTTP on localhost; credentials in URLs are rejected. Cloud credentials are delegated to Electron safeStorage by an injected secret service and never persisted in runtime SQLite state or package exports.

Provider configuration (`provider.save`) accepts `{type: 'openai'|'anthropic', endpoint, model, apiKey?}`. `provider.models` queries the provider model list; a model can also be entered manually. `provider.test` makes a real forced tool call and verifies the structured boolean output, so a plain chat-only endpoint is not reported as tool-capable. Structured output is delivered through validated tool arguments, not a universal provider-specific JSON response-format API. Vendor authorization errors, quota errors and malformed streams are reported without including raw provider error bodies. The test consumes a small provider request. Live account verification requires an owner-provided API key; protocol fixtures do not prove a particular account or model works.

`agent.run({message, appId?, pageId?, selection?, conversationId?, maxTokens?, maxTurns?})` starts asynchronously. `agent.status`, `agent.history`, `agent.cancel`, and `agent.approve` expose state. `agent.updated` carries stream updates; persisted transcripts contain completed tool results and usage. Maximums are 24 model turns, 1,000,000 reported tokens, five minutes per active segment and 8 MiB per streamed response. Defaults are 12 turns and 250,000 tokens. Token usage is cumulative across model calls, including repeated tool schemas and conversation context; it is not the size of one user message. Tokens are counted where the provider supplies usage, so token limits are checked between requests and can be exceeded by the final request. Turn/time/response limits still apply when usage is absent.

Budget stops expose `stopReason` (`token_budget` or `turn_limit`) and a Continue action. Continuing the same conversation preserves completed tool-call/result pairs and the created app, with a fresh per-request budget. Selecting a different app explicitly does not carry the previous app's transcript into that context. Existing persisted budget stops are recognized after an upgrade. Before an app exists, the provider is offered only workspace tools (platform/capability/schema/adapter discovery and app creation); app-specific tools become available after creation.

The assistant panel displays one conversation at a time. “Новый разговор” creates a fresh conversation ID and clears the composer and selected-document inclusion; previous messages are not sent to the provider. The currently open app remains the scope. “История” reopens saved conversations by their first message. The selected conversation is remembered locally for the workspace or app, including an empty new conversation. New/switch actions wait for an active request or approval to finish; closing the panel does not stop work, and reopening reconnects to the active request.

Live text uses `streamingText`, containing only the current model response. Committing a response appends it to `messages` and clears the live text in the same state change. The legacy `output` field remains aggregate output for the run and is never rendered as a live draft. Text equality is not used to identify messages: separate responses with identical wording remain separate messages. If streaming fails or is cancelled, the unfinished text remains visible once beside the error/status. `test:streaming` and `test:packaged:streaming` exercise delayed multi-round SSE through the real desktop UI.

Progress includes a safe phase (`waiting`, `thinking`, `preparing`, `answering`, `tool`) and activity timestamps. Reasoning/tool-argument chunks update activity without exposing their contents. The panel shows elapsed time and a neutral hint after 30 seconds without activity. Explicit output-limit stops reject the entire response before any tool executes, even if its JSON is parseable. Invalid arguments and incomplete responses preserve provider-reported usage in typed errors and offer an explicit retry using completed conversation history. Partial tool calls are never replayed. OpenAI `[DONE]` and Anthropic `message_stop` end streaming without waiting for the HTTP connection to close; cancellation also interrupts an idle reader. Five-minute timeout is reported separately from user cancellation. Compatible fixtures without a finish reason remain supported, so these checks cannot detect every well-formed but semantically incomplete response.

The system asks for a short plan before action. The agent must inspect an existing definition before preparing an update, can activate only drafts it prepared, and uses the core's validation, migration and stale-state checks. Tool arguments are validated against their catalog schemas. The current instance is supplied by the runtime, overwriting any model-supplied identifier. The agent cannot read secret storage, alter platform permissions, invoke a shell, or access arbitrary file paths. Tool/data/document output is marked untrusted in system instructions. Capability allowlisting and trusted app binding remain the actual enforcement boundary.

Confirmations cover deletion, new requested permissions, extension installation, potentially external actions and enabled background rules. Approval to include requested permissions never grants them: the user controls actual grants separately. Ordinary record edits and validated definition changes use already granted authority. Rejecting an approval cancels the pending run. After a crash, interrupted agent runs are marked failed rather than silently replaying a potentially completed action.

Only the user's message, supplied page/selection context, recent same-conversation text and explicitly requested tool results go to the provider. Document listing returns metadata, not document bodies; the model can read a document by explicit tool call for the user's task. Arbitrary folders, the global clipboard and all databases are never automatically collected. Tool results sent to the model are bounded to 64,000 characters. Provider prompts and model text are local history and are excluded from application packages.

`capabilities.list/search` exposes machine-readable capability records with stable version, input/output schema, effects, permissions, retry policy, errors, platform, cancellation/progress limits and examples. `definition_schema` returns the actual core JSON schema, JSON/XML/YAML/Base64/hex operations, action configurations and extension SDK examples. Workflows are built from these primitives, not fixed app templates. The action tool uses the same execution queue as buttons and automations. Package composition is available through `package_preview`; file export/import dialogs are shell operations the user performs from the package UI, and are not delegated file-path tools.

Run protocol and policy tests with `npx tsx --test tests/runtime.test.ts`.

Custom screens must set `config.extensionId` to an existing component extension; extension actions must reference a handler extension. Creation, definition updates and package import reject missing, unknown or wrong-kind references before persisting changes. `definition_schema` includes a complete screen/extension binding example and the SDK record contract: `records.list` returns `{records, total}`, fields live under `record.values`, and `records.upsert` accepts `{entityId, id?, values}`. Compilation and structural validation do not establish that arbitrary generated UI works; exercise its user workflow before claiming it is ready.

Protocol references checked during implementation: [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat), [Anthropic streaming](https://platform.claude.com/docs/en/build-with-claude/streaming), and [Anthropic model listing](https://platform.claude.com/docs/en/api/models/list). The Anthropic base URL includes `/v1`; API version header is `2023-06-01`. Compatible endpoints may support a narrower subset and must pass the real connection probe.
# Provider compatibility correction (0.1.1)

OpenCode requests identify this application using its own `everything-app/<version>` User-Agent and a stable opaque `x-opencode-session` derived from the conversation ID. Model discovery and connection probes receive their own session IDs. This provider-specific header is sent only to `opencode.ai`, never to unrelated or lookalike hosts. See [OpenCode Go's client requirements](https://opencode.ai/docs/go/#where-can-i-use-it).

DeepSeek Chat Completions use `max_tokens`, non-null assistant content, and automatic tool selection for the connection probe. Streamed `reasoning_content` is retained as private protocol metadata and replayed with complete tool-call/result history, including retained user rounds. It is excluded from visible answers, public run history and UI events. The execution queue owns a separate array so consuming pending tools cannot delete the assistant's tool calls. See [DeepSeek thinking-mode history](https://api-docs.deepseek.com/guides/thinking_mode/) and [integration guidance](https://api-docs.deepseek.com/quick_start/agent_integrations/oh_my_pi/).

HTTP 400/404/422 diagnostics inspect at most 8 KiB and translate recognized causes into fixed messages. Arbitrary response bodies and credentials are never copied into errors. `tests/provider-compatibility.test.ts` uses strict mocks for these contracts. `npm run test:provider` exercises the real Electron worker against a local mock HTTP server: connection probe, tool execution, and a follow-up user message. It also runs inside `test:workflows`; `test:packaged:provider` uses the built `.app`. These checks do not establish live account/model acceptance.

# Platform capability discovery (0.1.5)

`platform_capabilities` is a read-only agent tool available before app creation. It describes shipped capabilities of the shell and extension SDK, not only directly callable agent tools. The same guide is included in `definition_schema`. Search handles Russian and English multiword camera/microphone/overlay requests; the system prompt requires checking platform guidance before declaring a task unsupported.

The guide explains the permission-gated `sdk.call('system.media')` route, how the user grants access in app properties, state polling with cleanup and unknown/error handling, and the saved per-app “Поверх других окон” setting. It does not add a callable window-opening tool, auto-grant permissions, or claim reliable full-screen coverage or exact microphone capture detection. Native probe behavior is unchanged. Mock tests verify discovery delivery rather than the correctness of a live model’s eventual answer.

“Поверх других окон” is available in app properties and the settings button of a standalone window. It applies immediately to the separate window of that app and persists locally across reopening, including tray launches. Enabling it uses the macOS floating level and all-workspace visibility, including full-screen Spaces; disabling it restores ordinary stacking and workspace placement. The main workspace is unaffected. Each app has one resizable separate window, reused by the app menu, tray, and keyboard shortcut. Legacy compact and overlay opening requests reuse that same window and respect the saved preference. This is not a promise to cover lock screens or every higher-level system window. Bounds are saved per app and reused on reopening.

Since 0.1.11, windows bound to an app render a dedicated app-only root. They retain user-defined screens/actions and native macOS window controls, with no workspace rail, app management header, assistant, or workspace keyboard shortcuts. A single custom screen fills the native content area. Workspace navigation and restore-last-app preferences cannot redirect an app-only window. The main workspace remains the place to edit the app and manage permissions; document flushing still runs before closing app-only windows.
