# macOS: сигналы, окна и поставка

## Измеренный нативный адаптер

Swift CLI `native/MediaProbe.swift` с Foundation/CoreAudio/CoreMediaIO/AVFoundation компилируется `npm run native:build`; JSON через stdout, таймаут вызова 2 секунды, максимум 128 КБ. Он поставляется как доверенный ресурс Electron. Отдельный простой процесс выбран вместо ABI-модуля: нет привязки к Node ABI, сбой адаптера не завершает приложение. Чтение выполняется по запросу, а не бесконечным высокочастотным polling.

|Сигнал|Поддерживаемый API|Семантика и ограничения|Результат 02.10.2026 на MacBook Air M4 / 27.0|
|---|---|---|---|
|Аудиоустройство с входом|CoreAudio `kAudioDevicePropertyDeviceIsRunningSomewhere`, фильтр input streams|Активность устройства, не доказательство звонка, передачи голоса или mute. У duplex-устройства может отражать вывод.|Адаптер выполнен; inactive для перечисленных устройств в момент теста. Включение другим приложением не проверено.|
|Камера|CoreMediaIO `kCMIODevicePropertyDeviceIsRunningSomewhere`|Только перечисленные CMIO устройства; приложение-источник неизвестно; виртуальные/неперечисленные устройства могут не покрываться.|Адаптер выполнен; inactive для перечисленных устройств в момент теста. Браузер/видеозвонок не проверены.|
|Чужой захват экрана|Нет публичного общего API наблюдения|ScreenCaptureKit разрешает захват, но не является монитором всех чужих захватов.|unsupported|
|Mute звонка|Зависит от приложения|Нельзя вывести из активности микрофона.|unsupported|

Источники: https://developer.apple.com/documentation/coreaudio/kaudiodevicepropertydeviceisrunningsomewhere и https://developer.apple.com/documentation/coremediaio/kcmiodevicepropertydeviceisrunningsomewhere . Разрешение на захват не равно фактической активности. Нет доступного устройства/ошибка запроса → unknown. Отсутствие разрешения при известном отказе должно отличаться от inactive; текущие query API не дают надёжного универсального различения отказа и недоступности, поэтому возвращается unknown. Не подтверждён глобальный индикатор «всё выключено».

## Общая полка, быстрый запуск и история буфера

`src/main/shelf.ts` владеет единственным окном `mode=shelf`: отдельного окна launcher больше нет. Наведение и сочетание быстрого запуска открывают список приложений; сочетание истории и её пункты меню открывают встроенное приложение `builtin:clipboard` в том же окне. Реестр встроенных приложений находится в `src/shared/launcher.ts`; история хранится отдельно от настроек.

`Shelf.tsx` отвечает за геометрию и анимацию оболочки; `Launcher.tsx` — за поиск и переходы, `ClipboardHistory.tsx` — за историю. Повторное открытие быстрого запуска возвращает к списку. Настройка наведения перенесена в «Полка и быстрый запуск»; сохранённое значение используется без миграции.

Верхние углы прямые: `roundedCorners: false` отключает нативное скругление, нижние углы задаются CSS. Панель присоединяется к Spaces с `skipTransformProcessType: true`: её первое создание не должно менять activation policy всего приложения и скрывать значок Dock. Полка использует неактивирующую панель `type: panel`: приложение, активное до открытия, сохраняет меню в строке macOS. Вызов `app.focus()` здесь не нужен. И наведение, и открытие клавиатурой вызывают `show()` / `focus()` и передают фокус поиску: стрелки и Enter работают без предварительного щелчка. Намерение фокуса входит в снимок состояния, поэтому не теряется при поздней подписке renderer на события.

Чёрная панель начинается у верхнего края дисплея и визуально объединяется с вырезом; заголовок слева и кнопки справа располагаются на уровне camera safe area, с пустой центральной областью по ширине выреза. Поиск и список находятся ниже выреза. `enableLargerThanScreen` разрешает положение выше обычной границы строки меню, уровень `pop-up-menu` сохраняет видимость панели. Открытие за 200 мс раскрывает маску от размера выреза, закрытие за 150 мс сворачивает её обратно. Нативное окно скрывается после подтверждения анимации, с резервным таймером; повторное открытие отменяет ожидающее скрытие. При reduced motion переход выполняется сразу. `npm run test:clipboard:animation` проверяет реальную координату окна, фон, отступы, повторное открытие и reduced motion.

`native/ClipboardProbe.swift` собирается той же командой `npm run native:build` и поставляется как ресурс `clipboard-probe`. Процесс проверяет `NSPasteboard.changeCount` раз в 300 мс и сообщает только об изменениях; содержимое читает главный процесс через асинхронный Electron Clipboard API. Начальное содержимое не импортируется. При выходе помощник завершается, а незавершённая запись истории ожидается перед остановкой ядра.

Помощник также сообщает геометрию `NSScreen.safeAreaInsets` и областей `auxiliaryTopLeftArea` / `auxiliaryTopRightArea`, привязанную к идентификатору дисплея. Главный процесс переводит её в координаты Electron. Указатель проверяется раз в 80 мс; задержка наведения — 350 мс, ухода — 150 мс. Область между вырезом и панелью остаётся активной. На дисплеях без выреза используется верхняя центральная область шириной 96 точек. Оба способа открытия передают фокус панели; уход указателя после наведения по-прежнему закрывает её. Сон и блокировка независимо приостанавливают запись и наведение.

Автовставка использует двусторонний JSON-протокол с `clipboard-probe`. Перед захватом фокуса полкой помощник запоминает `NSRunningApplication`, AX-объекты окна и активного поля; в Electron передаётся только одноразовый токен, без содержимого поля. Переходы внутри полки сохраняют цель. После выбора запись попадает в pasteboard, полка скрывается, помощник поднимает исходное окно и проверяет, что активным стало именно сохранённое поле. Поле получает фокус после активации приложения. Если редактор пересоздал AX-объект, помощник ищет совпадающее текстовое поле в исходном окне по идентификатору или геометрии; содержимое поля не читается. Сохранённый диапазон выделения восстанавливается, если редактор это поддерживает. После стабилизации фокуса помощник отправляет полный Command-V через обычный поток событий `CGEvent.post(tap: .cghidEventTap)`, без повторной отправки. Если приложение завершилось, фокус не восстановился, сменился буфер или пользователь переключился в другую программу, вставка не выполняется. Сон и блокировка отменяют ожидающую вставку.

Разрешение Accessibility проверяется без запроса при открытии. Системный запрос появляется только по кнопке пользователя. Без доступа работает копирование; `pasteOnSelect` можно отключить, а Shift-Enter копирует без вставки. Старые файлы истории читаются с `pasteOnSelect: true` без потери прежних настроек. `npm run test:clipboard:paste` использует отдельный тестовый Electron-процесс с двумя полями, проверяет сохранение выделения, потерю фокуса и пересоздание rich-text редактора и восстанавливает буфер; при отсутствии разрешения проверяет fallback и явно сообщает, что нативная вставка не проверена.

История общая для платформы и хранится в `clipboard-history/history.enc` профиля через `safeStorage`. Записи и настройки заменяются атомарно через временный файл. Поддерживаются текст и PNG, ограничение размера и количества, срок хранения, закрепление и исключение стандартных confidential/transient/generated markers. Ошибка помощника или хранилища видна в панели и настройках. Пользовательские инструкции — в [README](../README.md#история-буфера-обмена), проверка — `npm run test:clipboard`.

## Воспроизводимая проверка на целевой 27.0.1

1. Соберите и запустите подписанную платформу, откройте полку и системный индикатор. Зафиксируйте оборудование, OS build, версии из `system.status`.
2. Запустите `build/media-probe` до, во время и после записи в Photo Booth/QuickTime и браузере с выданным доступом к камере/микрофону. Повторите с внешним устройством, virtual camera и только воспроизведением аудио на duplex-устройстве. Сравните с системным индикатором; не приравнивайте mute к неактивности.
3. Отзовите разрешения, отключите устройство, проверьте unknown/unsupported и диагностический текст. Screen capture чужого приложения остаётся unsupported.
4. Откройте окно на втором экране, отключите монитор. Окно должно остаться доступно. Попробуйте занятое сочетание клавиш — ожидается ошибка без перехвата чужой команды.

Эти пункты — сценарии приёмки, не заявления о выполненных ручных тестах.

## Подпись и обновления

Все сборки остаются ad-hoc signed (`identity: "-"`), без Developer ID и notarization. Это позволяет выполнять нативный ARM-код на Apple silicon, но не устанавливает доверие Apple к разработчику. `hardenedRuntime` отключён, entitlement разрешает JIT. Проверка готового bundle: `codesign --verify --deep --strict "release/mac-arm64/Polka.app"`. Обычная оценка Gatekeeper (`spctl`) может отклонить ad-hoc сборку; stapler для неё не применяется.

Первый скачанный DMG может потребовать разрешения запуска в настройках macOS. Sparkle обрабатывает quarantine при обновлении: ожидаемый сценарий — перезапуск без команд Terminal и повторного «Открыть всё равно». Сохранение Accessibility-разрешения для автоматической вставки не гарантируется при изменении ad-hoc подписи и требует проверки на отдельном Mac.

`npm run package` создаёт локальную сборку без канала обновлений. `npm run release` создаёт выпуск с нативным Sparkle через pinned `electron-sparkle-updater@0.5.2`. Отдельная Ed25519 подпись архива проверяется публичным ключом, встроенным в `Info.plist`; она не является Apple code signing. Проверка обязательна **до распаковки** (`SUVerifyUpdateBeforeExtraction`). Подпись ZIP и публичный ключ дополнительно проверяются Node.js при выпуске. Открытые GitHub Releases служат единственным хранилищем; отдельный сервер и GitHub Pages не требуются.

## Настройка выпуска (один раз)

На Apple silicon Mac с Node, Xcode Command Line Tools и `gh`:

```sh
npm ci
npm run sparkle:build
node_modules/electron-sparkle-updater/native/vendor/bin/generate_keys
node_modules/electron-sparkle-updater/native/vendor/bin/generate_keys -x /secure/path/sparkle-private-key
```

Sparkle создаёт ключ в login Keychain; при наличии ключа использует его. Сохраните защищённую резервную копию. Публичный ключ из вывода `generate_keys` задайте как **variable** `SPARKLE_PUBLIC_KEY` в GitHub environment `release`. Содержимое экспортированного файла задайте как **secret** `SPARKLE_PRIVATE_KEY` в той же среде. Приватный ключ нельзя помещать в Git, артефакты, командные аргументы или логи. Потеря ключа для ad-hoc выпуска может потребовать ручной переустановки пользователями; не генерируйте новый ключ для очередной версии.

Workflow берёт версию приложения и имена архивов из тега GitHub Release (с необязательным префиксом `v`); appcast ссылается на исходный тег. Менять `package.json` для выпуска не требуется.

Для локального выпуска передайте через окружение `RELEASE_REPOSITORY=mishankov/polka`, `SPARKLE_PUBLIC_KEY`, `SPARKLE_PRIVATE_KEY` и, только для загрузки черновика, `GH_TOKEN`. Необязательный `RELEASE_TAG` задаёт тег и версию; без него используется `v` + версия `package.json`. Apple credentials не нужны. Переменные не сохраняются в конфигурацию сборки; приватный ключ передаётся `sign_update` через stdin.

## Полный поток выпуска

1. Выбрать новый тег версии (`vVERSION` или `VERSION`). Уже опубликованные версии и архивы не заменять.
2. Запустить `.github/workflows/release.yml` вручную с тегом `vVERSION` или `npm run release -- --publish` локально.
3. Команда собирает приложение, Swift helpers и Sparkle bridge, упаковывает DMG/ZIP, подписывает готовый ZIP, создаёт `appcast.xml`, проверяет signature/размер/URL/версию, codesign, целостность DMG и packaged shelf smoke.
4. Workflow загружает ZIP, DMG и checksums, затем appcast. При ручном запуске выпуск остаётся черновиком до завершения загрузки, затем workflow публикует его. `npm run release -- --publish` локально только создаёт черновик: его следует опубликовать вручную после проверки. Предпочитайте ручной запуск workflow с черновиком; при событии `release: published` feed временно недоступен, пока сборка и загрузка не завершены. Пререлизы и черновики не попадают в stable latest. Уже публичные assets не перезаписываются; повторная загрузка staging assets разрешена только для черновиков.

Feed: `https://github.com/mishankov/polka/releases/latest/download/appcast.xml`. Он содержит точный immutable URL ZIP вида `.../releases/download/TAG/polka-VERSION-arm64.zip`, версию, минимальную macOS и Ed25519 signature. GitHub latest должен указывать на новейший стабильный выпуск с appcast; не выбирайте старый выпуск вручную как latest. Приложение сверяет версии через Sparkle и не предлагает downgrade. DMG предназначен для первой установки; обновления используют ZIP. Squirrel `latest-mac.yml` и blockmap не используются (builder может создать неиспользуемый ZIP blockmap, он не публикуется).

В `.github/workflows/release.yml` используется тот же hosted Apple silicon `xcode-27`, что в CI. Сначала `npm run verify`, затем `npm run release`, загрузка архивов, appcast и публикация черновика при ручном запуске. Защищённая environment `release` хранит ключ и может требовать approval владельца.

## Поведение приложения

Выпуск проверяет обновления при запуске и затем каждые шесть часов. Найденный ZIP загружается и проверяется в фоне; настройки показывают прогресс, затем «Установить и перезапустить». Сеть или неправильная подпись дают ошибку с возможностью повторной проверки и не мешают работе полки. Локальные/CI-сборки не обращаются к feed.

Перед явной установкой окна блокируют ввод и сохраняется история буфера. Ошибка сохранения отменяет перезапуск, сохраняет готовое обновление и восстанавливает окна. Worker настроек остаётся запущенным, пока Sparkle подготавливает обновление; при ошибке staging окна снова доступны. Native-событие `before-quit-for-update` запускает штатный выход Electron с остановкой полки, индикатора и worker настроек. При обычном выходе история также сохраняется. Данные живут в пользовательском профиле вне `.app` и не заменяются updater.

Стандартный Sparkle может установить staged update при обычном выходе. Поэтому `scripts/sparkle-bridge.patch` добавляет native API отмены staging и событие готовности installer к pinned bridge. Событие запускает штатный Electron quit только после подготовки installer. `npm run sparkle:build` применяет патч идемпотентно и прекращает сборку, если исходник изменился. Обычный выход после сохранения вызывает отмену; явный update restart сохраняет staging. Автоустановка при обычном выходе не разрешена. При обновлении bridge этот патч и smoke необходимо пересмотреть.

## Проверка настоящего обновления

`npm run test:updates` собирает два реальных ad-hoc `.app` с отдельным appId, временным Ed25519 ключом и localhost feed. Проверяет отклонение неправильной подписи, автоматическую загрузку, отсутствие установки до подтверждения, отмену staging при обычном выходе, установку/перезапуск новой версии и сохранность пользовательской настройки. Тест ничего не публикует, не использует production ключи и удаляет свои bundles/profile. Нужна desktop-сессия macOS; в T3 при необходимости снять `ELECTRON_RUN_AS_NODE` (`env -u ELECTRON_RUN_AS_NODE npm run test:updates`).

Отдельная приёмка перед первым production выпуском: две последовательные версии в GitHub, чистый Mac, первая установка в /Applications, обновление через настоящий HTTPS feed, сохранность истории и Accessibility-разрешений. Локальный smoke проверяет реальный native installer/relaunch, но не первый Gatekeeper launch, права администратора, сохранность системных разрешений или доставку GitHub. Старые установки без Sparkle требуют одного ручного обновления.
