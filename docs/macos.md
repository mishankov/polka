# macOS: сигналы, окна и поставка

## Измеренный нативный адаптер

Swift CLI `native/MediaProbe.swift` с Foundation/CoreAudio/CoreMediaIO/AVFoundation компилируется `npm run native:build`; JSON через stdout, таймаут вызова 5 секунд, максимум 128 КБ. Он поставляется как доверенный ресурс Electron; `.everyapp` не может подменять или добавлять нативный бинарник. Отдельный простой процесс выбран вместо ABI-модуля: нет привязки к Node ABI, сбой адаптера не завершает приложение. Чтение выполняется по запросу, а не бесконечным высокочастотным polling.

|Сигнал|Поддерживаемый API|Семантика и ограничения|Результат 02.10.2026 на MacBook Air M4 / 27.0|
|---|---|---|---|
|Аудиоустройство с входом|CoreAudio `kAudioDevicePropertyDeviceIsRunningSomewhere`, фильтр input streams|Активность устройства, не доказательство звонка, передачи голоса или mute. У duplex-устройства может отражать вывод.|Адаптер выполнен; inactive для перечисленных устройств в момент теста. Включение другим приложением не проверено.|
|Камера|CoreMediaIO `kCMIODevicePropertyDeviceIsRunningSomewhere`|Только перечисленные CMIO устройства; приложение-источник неизвестно; виртуальные/неперечисленные устройства могут не покрываться.|Адаптер выполнен; inactive для перечисленных устройств в момент теста. Браузер/видеозвонок не проверены.|
|Чужой захват экрана|Нет публичного общего API наблюдения|ScreenCaptureKit разрешает захват, но не является монитором всех чужих захватов.|unsupported|
|Mute звонка|Зависит от приложения|Нельзя вывести из активности микрофона.|unsupported|

Источники: https://developer.apple.com/documentation/coreaudio/kaudiodevicepropertydeviceisrunningsomewhere и https://developer.apple.com/documentation/coremediaio/kcmiodevicepropertydeviceisrunningsomewhere . Разрешение на захват не равно фактической активности. Нет доступного устройства/ошибка запроса → unknown. Отсутствие разрешения при известном отказе должно отличаться от inactive; текущие query API не дают надёжного универсального различения отказа и недоступности, поэтому возвращается unknown. Не подтверждён глобальный индикатор «всё выключено».

## Общая полка, быстрый запуск и история буфера

`src/main/shelf.ts` владеет единственным окном `mode=shelf`: отдельного окна launcher больше нет. Наведение и сочетание быстрого запуска открывают список приложений; сочетание истории и её пункты меню открывают встроенное приложение `builtin:clipboard` в том же окне. Реестр встроенных приложений находится в `src/shared/launcher.ts`; Clipboard не создаёт пользовательский экземпляр и не попадает в экспорт `.everyapp`.

`Shelf.tsx` отвечает за геометрию и анимацию оболочки; `Launcher.tsx` — за поиск и переходы, `ClipboardHistory.tsx` — за историю. Перед сменой назначения главный процесс ожидает подтверждение сохранения черновиков. Повторное открытие быстрого запуска возвращает к списку. При открытии личного приложения полка расширяется до 960 × 680 точек плюс отступ выреза в пределах дисплея. Настройка наведения перенесена в «Полка и быстрый запуск»; сохранённое значение используется без миграции.

Верхние углы прямые: `roundedCorners: false` отключает нативное скругление, нижние углы задаются CSS. Панель присоединяется к Spaces с `skipTransformProcessType: true`: её первое создание не должно менять activation policy всего приложения и скрывать значок Dock. Полка использует неактивирующую панель `type: panel`: приложение, активное до открытия, сохраняет меню в строке macOS. Вызов `app.focus()` здесь не нужен. И наведение, и открытие клавиатурой вызывают `show()` / `focus()` и передают фокус поиску: стрелки и Enter работают без предварительного щелчка. Намерение фокуса входит в снимок состояния, поэтому не теряется при поздней подписке renderer на события.

Чёрная панель начинается у верхнего края дисплея и визуально объединяется с вырезом; заголовок слева и кнопки справа располагаются на уровне camera safe area, с пустой центральной областью по ширине выреза. Поиск и список находятся ниже выреза. `enableLargerThanScreen` разрешает положение выше обычной границы строки меню, уровень `pop-up-menu` сохраняет видимость панели. Открытие за 200 мс раскрывает маску от размера выреза, закрытие за 150 мс сворачивает её обратно. Нативное окно скрывается после подтверждения анимации, с резервным таймером; повторное открытие отменяет ожидающее скрытие. При reduced motion переход выполняется сразу. `npm run test:clipboard:animation` проверяет реальную координату окна, фон, отступы, повторное открытие и reduced motion.

`native/ClipboardProbe.swift` собирается той же командой `npm run native:build` и поставляется как ресурс `clipboard-probe`. Процесс проверяет `NSPasteboard.changeCount` раз в 300 мс и сообщает только об изменениях; содержимое читает главный процесс через асинхронный Electron Clipboard API. Начальное содержимое не импортируется. При выходе помощник завершается, а незавершённая запись истории ожидается перед остановкой ядра.

Помощник также сообщает геометрию `NSScreen.safeAreaInsets` и областей `auxiliaryTopLeftArea` / `auxiliaryTopRightArea`, привязанную к идентификатору дисплея. Главный процесс переводит её в координаты Electron. Указатель проверяется раз в 80 мс; задержка наведения — 350 мс, ухода — 150 мс. Область между вырезом и панелью остаётся активной. На дисплеях без выреза используется верхняя центральная область шириной 96 точек. Оба способа открытия передают фокус панели; уход указателя после наведения по-прежнему закрывает её. Сон и блокировка независимо приостанавливают запись и наведение.

Автовставка использует двусторонний JSON-протокол с `clipboard-probe`. Перед захватом фокуса полкой помощник запоминает `NSRunningApplication`, AX-объекты окна и активного поля; в Electron передаётся только одноразовый токен, без содержимого поля. Переходы внутри полки сохраняют цель. После выбора запись попадает в pasteboard, полка скрывается, помощник поднимает исходное окно и проверяет, что активным стало именно сохранённое поле. Поле получает фокус после активации приложения. Если редактор пересоздал AX-объект, помощник ищет совпадающее текстовое поле в исходном окне по идентификатору или геометрии; содержимое поля не читается. Сохранённый диапазон выделения восстанавливается, если редактор это поддерживает. После стабилизации фокуса помощник отправляет полный Command-V через обычный поток событий `CGEvent.post(tap: .cghidEventTap)`, без повторной отправки. Если приложение завершилось, фокус не восстановился, сменился буфер или пользователь переключился в другую программу, вставка не выполняется. Сон и блокировка отменяют ожидающую вставку.

Разрешение Accessibility проверяется без запроса при открытии. Системный запрос появляется только по кнопке пользователя. Без доступа работает копирование; `pasteOnSelect` можно отключить, а Shift-Enter копирует без вставки. Старые файлы истории читаются с `pasteOnSelect: true` без потери прежних настроек. `npm run test:clipboard:paste` использует отдельный тестовый Electron-процесс с двумя полями, проверяет сохранение выделения, потерю фокуса и пересоздание rich-text редактора и восстанавливает буфер; при отсутствии разрешения проверяет fallback и явно сообщает, что нативная вставка не проверена.

История общая для платформы и хранится в `clipboard-history/history.enc` профиля через `safeStorage`; личные приложения и их экспорт не получают её автоматически. Записи и настройки заменяются атомарно через временный файл. Поддерживаются текст и PNG, ограничение размера и количества, срок хранения, закрепление и исключение стандартных confidential/transient/generated markers. Ошибка помощника или хранилища видна в панели и настройках. Пользовательские инструкции — в [README](../README.md#история-буфера-обмена), проверка — `npm run test:clipboard`.

## Воспроизводимая проверка на целевой 27.0.1

1. Соберите и запустите подписанную платформу, откройте «Входящие»/системный индикатор. Зафиксируйте оборудование, OS build, версии из `system.status`.
2. Запустите `build/media-probe` до, во время и после записи в Photo Booth/QuickTime и браузере с выданным доступом к камере/микрофону. Повторите с внешним устройством, virtual camera и только воспроизведением аудио на duplex-устройстве. Сравните с системным индикатором; не приравнивайте mute к неактивности.
3. Отзовите разрешения, отключите устройство, проверьте unknown/unsupported и диагностический текст. Screen capture чужого приложения остаётся unsupported.
4. Включите правило с background + clipboard.read, закройте все окна. Изменение буфера должно дать задание. Остановка экземпляра или отзыв права должны прекратить наблюдение.
5. Усыпите Mac дольше интервала; после пробуждения проверьте политики skip/once/catchup. Полностью завершите процесс в середине внешнего эффекта — запись должна стать interrupted, не повторяться молча.
6. Откройте окно на втором экране, отключите монитор. Окно должно остаться доступно. Попробуйте занятое сочетание клавиш — ожидается ошибка без перехвата чужой команды.
7. Установите DMG в /Applications, дважды откройте `.everyapp`. Должен появиться предпросмотр без выполнения кода. Отмена не создаёт экземпляр. Повторный импорт создаёт новую копию.

Эти пункты — сценарии приёмки, не заявления о выполненных ручных тестах.

## Подпись, notarization, обновления

`npm run package` создаёт arm64 DMG + ZIP без Developer ID и notarization. Локальная упаковка явно использует ad-hoc подпись (`identity: "-"`), необходимую для выполнения нативного ARM-кода на Apple silicon; полностью удалять подписи нельзя. `hardenedRuntime` отключён, entitlement разрешает JIT. Подпись готового bundle проверяется командой `codesign --verify --deep --strict "release/mac-arm64/Polka.app"`. После переноса Gatekeeper может потребовать разрешение на запуск: ad-hoc подпись не делает сборку доверенным выпуском.

Production: команда `npm run release` выбирает сертификат Developer ID, включает `hardenedRuntime` и notarization. Предоставьте `CSC_LINK`/`CSC_KEY_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID` или поддерживаемый electron-builder App Store Connect API key. Секреты передаются через секретное хранилище CI, не `.env` в Git.

Задайте RELEASE_REPOSITORY=owner/repository и защищённые credentials CI для команды release. Нельзя выпускать релиз в чужой репозиторий/подписывать чужим сертификатом. Перед выпуском `codesign --verify --deep --strict`, `spctl --assess --type execute`, `xcrun stapler validate` и перенос на чистый Mac. Автообновления electron-updater только для установленной подписанной платформы; скачивание не происходит автоматически. Release/update rollback на другой установленной версии здесь не проверен.


## Полный поток выпуска и обновления

`.github/workflows/release.yml` повторяет поток camunda-stub-worker: опубликованный GitHub Release запускает сборку его тега; ручной запуск с `tag` и `prerelease` создаёт или переиспользует выпуск и публикует черновик после загрузки. Все jobs выполняются на hosted Apple silicon/macOS 27 (`xcode-27`). Тег должен иметь вид `vVERSION` и совпадать с `package.json`. DMG, ZIP и SHA-256 `checksums.txt` загружаются в GitHub Release. Это ad-hoc сборки без notarization и канала автообновлений; подписанный поток описан ниже.

`npm run release` проверяет обязательные `RELEASE_REPOSITORY=owner/repository`, `CSC_LINK`, `CSC_KEY_PASSWORD` и Apple credentials. Оно собирает с `forceCodeSigning` и notarize для .app, затем выполняет codesign/spctl/stapler, проверку целостности DMG и packaged smoke. Подписанное notarized .app поставляется внутри DMG/ZIP; архивы после создания не меняются, чтобы сохранить корректность updater checksums/blockmap. `npm run release -- --publish` после всех проверок загружает артефакты через `gh` в **черновик** GitHub Release. Требуются GH_TOKEN и установленный gh. Секреты не записываются в конфигурацию артефакта. Обычный `npm run package` продолжает создавать локальную неподписанную сборку без канала обновлений.

В настройках подписанного выпуска: «Проверить обновления» → «Загрузить обновление» (процент загрузки) → «Сохранить и перезапустить». Самопроизвольная загрузка/установка, prerelease и downgrade выключены. Перед рестартом все окна подтверждают сохранение черновиков; ошибка сохранения не разрешает установку. Данные находятся в пользовательском профиле вне bundle, package builder его не включает и updater его не заменяет. Локальная сборка показывает честное отсутствие канала вместо попытки обратиться к вымышленному репозиторию.

Приёмка настоящего обновления: выпустить две последовательные подписанные версии в выбранном репозитории, установить первую в /Applications на чистом Mac, создать запись и несохранённый документ, проверить обновление/загрузку/явный рестарт и сохранность данных во второй версии. Повторить с отказом сети и ошибкой сохранения. До выполнения этого прогона нельзя считать реальное обновление подтверждённым; unit-тесты проверяют состояния через mock adapter.

Подписанный release использует безопасные для GitHub имена `polka-VERSION-arm64.dmg` и `polka-VERSION-arm64.zip` (плюс blockmap и `latest-mac.yml`). Обычная локальная упаковка использует имя продукта из конфигурации `productName: "Polka"`. Перед загрузкой `release:verify` проверяет, что URL в метаданных точно совпадают с именами загружаемых файлов, а SHA-512 и размеры соответствуют готовым архивам.

После команды установки окна временно не принимают ввод, и их черновики сохраняются. Core остаётся запущенным, пока Squirrel проверяет и подготавливает обновление; при ошибке staging или сохранения окна снова доступны. Только native-событие `before-quit-for-update` переключает обработчики окон в режим завершения без повторной блокировки close. Core получает запрос завершения без ожидания: если выход опередит остановку фоновой работы, следующий запуск применяет существующую политику interrupted без слепого повторения внешних эффектов. Живое обновление между подписанными версиями остаётся обязательной отдельной приёмкой.
