# Как писать примечания к выпускам

Примечания должны помочь пользователю понять, что изменилось и как этим воспользоваться. Файл `release-notes/VERSION.json` содержит одинаковые по смыслу изменения на русском (`ru`) и английском (`en`); оба поля обязательны и ограничены 20 000 символами каждое.

## Содержание

- Начните с двух–трёх самых заметных изменений. Описывайте результат: «Полка возвращает поиск и выбранную запись при повторном открытии», а не название внутреннего рефакторинга.
- В одном пункте описывайте одно изменение. Обычно достаточно одного–двух предложений; сочетание клавиш или конкретный сценарий полезнее перечня внутренних деталей.
- У исправления укажите, когда возникала проблема и что теперь происходит. Не обещайте исправления, которые не подтверждены diff и проверками.
- Если изменение требует действия пользователя, объясните его прямо в соответствующем пункте: например, необходимость заново выдать «Универсальный доступ» при смене подписи.
- При длинном списке отделяйте «Новое», «Исправления» и «Для разработчиков» пустыми строками и обычными текстовыми заголовками. Изменения тестов и инструментария помещайте после изменений для пользователя.
- Переводите конкретные действия и ограничения, а не только заголовки. Интерфейс Полки остаётся на русском; в английских примечаниях оставляйте русское название нужного пункта меню рядом с переводом.

В приложении текст показывается без HTML и Markdown, поэтому используйте обычные строки и `•` для пунктов. Не вставляйте Markdown-ссылки, fenced code blocks или технические отчёты о CI в эти поля.

## Пример

```json
{
  "ru": "Новое\n• Полка возвращает поиск и выбранную запись при повторном открытии в течение минуты.\n\nИсправления\n• При медленной подготовке буфера уход указателя больше не отменяет выбранную вставку.",
  "en": "New\n• Reopening the shelf within one minute restores your search and selected item.\n\nFixes\n• When clipboard preparation is slow, moving the pointer away no longer cancels the selected paste."
}
```

Это пример формата, а не список изменений следующего выпуска. Опубликованные файлы прошлых выпусков не переписывайте ради новой структуры.

## GitHub и приложение

Генератор `scripts/release-notes.mjs` добавляет к GitHub Release номер версии, требования macOS 27+/Apple silicon, отдельные разделы «Что нового» и «Обновление» и три способа установки на обоих языках. Установка находится в раскрываемых блоках, чтобы изменения были видны сразу. Маркеры `•` становятся Markdown-списками. Ссылки на DMG указывают на конкретный тег выпуска; скрипт установки всегда скачивает последний стабильный выпуск. Инструкции по установке не нужно дублировать в JSON каждого выпуска.

В appcast отправляются только исходные `ru` и `en`, поэтому окно «Что нового» внутри уже установленной Полки показывает изменения без повторной инструкции по установке.

Перед выпуском проверьте обе версии текста и сгенерированное описание:

```sh
node scripts/release-notes.mjs vVERSION /tmp/polka-release-notes.md
```

Команда не требует npm-зависимостей или ключей подписи. Для другого репозитория задайте `RELEASE_REPOSITORY=owner/repository`; в GitHub Actions используется `GITHUB_REPOSITORY`. Полный процесс подготовки и публикации описан в [документации macOS](macos.md#полный-поток-выпуска).
