# Documents and local editing

The text and raster screens open multiple files or a folder and accept native file/folder drops. Folder traversal skips hidden entries and symbolic links, limits traversal to 2,048 entries and 16 directory levels, and opens at most 256 files / 64 MiB per selection (32 MiB per file). A file already open in the same app activates its existing draft instead of replacing it from disk. All document kinds share the tab list; initial activation prefers the screen’s document kind, and opening a tab chooses its text, binary, or raster editor automatically.

Text documents expose encoding and line-ending controls, close, save/save-as, persistent draft undo/redo, and the existing CodeMirror editing history. Applying transformations changes drafts, never writes over external files. Saving retains external-change detection and atomic replacement. Batch apply checks every document revision before modifying any document; stale previews must be regenerated.

The transformation panel builds explicit typed chains for entered text, editor selection, current document, clipboard, and a selected set of opened files. Native file selection is also available in the file-set mode. Preview shows each file's result or the failed step and parser diagnostic, and offers explicit draft application or a new document. Clipboard reads and writes occur only from explicit UI actions. JSON/XML mapping warnings appear before execution. Byte-oriented hex/Base64, JSON/XML parse, and typed PNG image operations are included, and incompatible adjacent chain types are rejected. Image documents use a bounded PNG image value; PNG bytes can decode into the image type, participate in crop/resize/rotate/flip chains, and encode back to bytes. Image previews show the resulting pixels and dimensions, and applying them updates image drafts with the same revision checks. Native PNG image clipboard reads and writes are supported alongside text.

Preview jobs run in a dedicated Node worker, outside the UI and core-service worker. Progress counts actual completed file/step work. Cancellation terminates the worker, including during a synchronous parser call. Closing the panel cancels/releases its preview. Two concurrent previews are allowed, with a 2-minute execution limit and a 256 MiB worker heap limit. Input is bounded incrementally before binary-array expansion: 32 MiB serialized input/output per job, up to 64 steps, and 16 MiB serialized input per step. Completed previews are transient, bounded, and do not persist across restart; source drafts do persist.

Image chains use pinned `pngjs@7.0.0` ([upstream API documentation](https://github.com/pngjs/pngjs)) for decode/encode. Before decoding, the worker checks PNG signature, a single IHDR, dimensions, chunk bounds, and animation/interlace/bit-depth constraints. Supported input is static non-interlaced PNG with depth up to 8 bits, no more than 16 megapixels, 8,192 pixels per side, and 12 MiB encoded. Output is 8-bit RGBA PNG; metadata and color profiles are dropped, and resizing uses nearest-neighbor sampling. These limits and losses appear before execution. Base64 validation uses linear alphabet/padding checks and is regression-tested on a valid 4 MiB payload.

The raster editor supports brush, eraser, resize, rectangular crop by coordinates, clockwise/counterclockwise rotation, horizontal/vertical reflection, and undo/redo of both drawing and geometry changes. Operations modify canvas pixels and export PNG; dimensions are limited to 8,192 pixels per side and 16 megapixels. The document's draft/history records committed edits for recovery.

Validation:

- `npx tsx --test tests/document-workflows.test.ts`: native path scanning, typed chains, per-file worker failures, cancellation, incremental memory limits, revision-checked atomic apply, typed undo/redo, raster bounds, full image decode/geometry/encode pixel chains, PNG allocation guards, large Base64, image worker previews and stale image-apply rejection.
- `npx tsx scripts/document-workflows-smoke.ts` after a build: native folder chooser fixture, multiple tabs, native dropped File handling, selection and clipboard chains, file-set apply, and pixel-preserving raster crop/rotation/undo, typed image chains with visual previews, native image clipboard, and applying PNG results back to the raster draft. Screenshots and results use `artifacts/document-*`.

Current limits are deliberate: the image chain accepts the documented PNG subset; JPEG/GIF/WebP editing in the raster editor emits PNG and saving a changed codec opens Save As with the correct extension. Crop uses numeric coordinates rather than a draggable marquee, and batch disk overwrite is not implicit. Native directory grants belong only to the user-selected import; they do not grant extensions arbitrary filesystem access.
