# Хранение данных

Профиль Electron содержит настройки в таблице `settings` файла `workspace.sqlite`, зашифрованную историю буфера и настройки полки. Для испытаний профиль переопределяется переменной `EVERYTHING_PROFILE`.

Разные checkout используют отдельные постоянные профили разработки. Профиль установленного приложения не меняется. [Пути и выбор профиля](development.md).

Настройки быстрого запуска и индикатора сохраняются через отдельный worker SQLite. Он открывает существующую таблицу настроек, поэтому обновление сохраняет выбранные сочетания и поведение индикатора.

Под ключом `launcherUsage` в той же таблице хранится локальная статистика успешных запусков программ через полку: идентификатор из каталога, число запусков и время последнего запуска. Запросы поиска не сохраняются. Статистика не синхронизируется между Mac и используется для порядка сопоставимых совпадений; ошибки запуска не увеличивают счётчик. Ошибка записи статистики не мешает открытию программы.

Выбор «Пропустить эту версию» и срок «Напомнить завтра» хранятся в той же таблице под ключом `updatePreferences`. Они относятся к конкретной версии и сохраняются после перезапуска; более новое обновление не скрывается этим выбором.

Удаление пользовательских приложений и LLM-провайдеров из продукта не удаляет их ранее сохранённые данные. Старые таблицы, вложения и файлы секретов остаются в профиле; приложение больше не читает и не запускает их. API импорта, экспорта, запуска приложений, моделей и фоновых заданий отсутствуют.

История хранит текст и PNG локально в зашифрованном файле. Лимиты и правила очистки описаны в README. Настройки не предназначены для хранения секретов.

Закреплённый текст можно превратить в сниппет с необязательным названием (до 120 символов) и редактировать его текст. Название и текст хранятся в том же зашифрованном файле версии 1; старые файлы без новых полей читаются без миграции. Создание закрепляет запись; последующее редактирование сохраняет её текущий статус закрепления. После открепления действует обычный срок хранения. Изображения и обычные текстовые записи по-прежнему можно закреплять без создания сниппета.

Обычная запись имеет SHA-256 ID содержимого. При создании сниппета её ID удаляется с синхронизируемой отметкой удаления, а сниппет получает случайный 256-битный ID, неизменный при редактировании. Одинаковый текст у разных сниппетов или обычной записи допустим: сохранение не объединяет их и не заменяет чужое название. Повторный захват текста существующего сниппета не создаёт лишнюю запись. Одновременное преобразование исходной записи на двух отключённых Mac создаёт два независимых сниппета.

Синхронизация сниппетов расширяет протокол версии 1: заголовок `x-everything-snippets: 1` и поле `snippets: true` в манифесте согласуют поддержку. Сниппет помечен `snippet: true` в записи манифеста и передаваемом содержимом. Штамп `added` служит версией пары «название + текст», `seen` — полученной версией; последнее изменение по логическим часам побеждает целиком, при равенстве счётчика используется ID устройства. Закрепление имеет отдельный штамп, поэтому редактирование не отменяет изменение закрепления на другом Mac. Удаление и очистка используют существующие отметки. Редактор отклоняет сохранение, если текст или название изменились после его открытия, сохраняя введённый вариант для пользователя.

Для старых Mac манифест и передача содержимого исключают сниппеты, включая их отметки, но сохраняют удаления исходных записей и обычную историю. Для синхронизации сниппетов обновите обе копии Polka. Обратное открытие нового файла в старой версии приложения не поддерживается: старая версия не сохраняет новые поля.

Ключ шифрования установленной macOS-сборки хранится в Связке ключей под именем `polka Safe Storage`. Перед первым доступом в каждой версии приложение объясняет возможный системный запрос; подтверждённая версия записывается в файл `keychain-notice-version` профиля отдельно от зашифрованной истории. Этот файл содержит только номер версии, без ключа или пароля. При отказе в доступе к ключу история и синхронизация недоступны, а зашифрованные файлы сохраняются. После перезапуска запрос можно повторить.

Смена регистра в просмотре не изменяет сохранённую запись: при копировании или вставке используется выбранное преобразование исходного текста. Сам выбор преобразования не сохраняется в профиле. Запрос, выбор, просмотр, преобразование и прокрутка истории, а также категория и оттенок эмодзи удерживаются в памяти последнего подтверждённого представления для быстрого повторного открытия полки; после перезапуска приложения этот контекст не восстанавливается. «Сохранить изображение…» записывает отдельный PNG в выбранное пользователем место без шифрования истории; исходная запись остаётся в истории.

При ошибке чтения, расшифровки или формата истории исходный `clipboard-history/history.enc` сохраняется без замены. Пока нельзя прочитать связанные настройки, наведение, сочетание истории и автовставка отключены; запуск полки и копирование эмодзи доступны. Ошибка записи останавливает сбор, изменения и синхронизацию, оставляя уже прочитанную историю доступной для просмотра и копирования. Ошибка `clipboard-history/sync.enc` останавливает только синхронизацию. Сброса, временного хранилища или переноса настроек нет; восстановите доступ к файлу и перезапустите приложение. Перед ручной заменой сохраните зашифрованную копию.
